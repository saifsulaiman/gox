# GOX Code Generation & Transformation Engine

## 1. Overview

GOX v0.9 introduces the **Code Generation & Transformation Engine**, enabling full end-to-end compilation (`gox build`) and direct execution (`gox run`) of standard, unmodified Go 1.24+ programs.

The engine translates proven memory strategy decisions generated by the GOX static analyzer directly into high-performance native Go code backed by deterministic runtime allocators, drastically reducing or eliminating dependence on the tracing garbage collector.

```
                      +-----------------------------+
                      |   Standard Go 1.24+ Code    |
                      +--------------+--------------+
                                     |
                                     v
                      +-----------------------------+
                      |    GOX 7-Tier Strategy      |
                      |    Inference Engine         |
                      +--------------+--------------+
                                     |
                         Proven Memory Decisions
                                     |
                                     v
                      +-----------------------------+
                      |    GOX AST Transformer      |
                      |  - Immortal/Static Rewrite  |

                      |  - Arena Lifecycle Inject   |
                      |  - ARC / Weak Boxing        |

                      +-----------------------------+

                      |  (Zero GC overhead on       |
                      |     proven allocations)     |
                      +-----------------------------+
```

## 2. Core Architectural Principles

1. **100% Unmodified Go Syntax**:
   Developers write idiomatic Go source code. No language annotations (`[static]`, `immortal`, `unique`), lifetime syntax, or custom pointer types are introduced.

2. **Sound Mathematical Verification**:
   Transformations are applied **only** to allocation sites possessing formal `PROVEN` confidence. Any allocation involving unmodeled constructs (channels, unverified interfaces, reflection, `unsafe.Pointer`, or FFI boundaries) remains untouched and falls back to standard Go GC (`TRACING_FALLBACK`).

3. **Exact Type and ABI Preservation**:
   All transformed allocation functions (`AllocImmortal`, `AllocReadOnly`, `AllocVal`, `AllocUnique`) return standard Go pointers (`*T`), perfectly matching the type and ABI of original `&T{...}` and `new(T)` expressions. Field selectors, method sets, and interface assertions continue to function identically with zero call-site rewriting.

4. **Self-Contained Embedded Runtime (`goxrt`)**:
   During compilation, GOX automatically stages an embedded, zero-dependency runtime package (`goxrt`) inside the build tree. The compiled binary requires no external network access, third-party module downloads, or remote repositories.

## 3. Transformation Strategies

| Strategy | Original Syntax | Transformed Code | Runtime Mechanism |
| :--- | :--- | :--- | :--- |
| **Immortal / Static** | `&Config{...}` (global / init) | `goxrt.AllocImmortal(Config{...})` | Process-lifetime bump allocator (`0.81 ns/op`); zero GC root scanning or write barriers. |
| **Immortal Read-Only** | `&LookupTable{...}` | `goxrt.AllocReadOnly(LookupTable{...})` | Immutable static memory pool; zero GC tracking. |
| **Region / Arena** | `&Item{...}` (function-local) | `goxrt.AllocVal(_goxArena, Item{...})` | Function-scoped bump arena; bulk $O(1)$ release via `defer goxrt.Free(_goxArena)`. |
| **Unique Owned** | `&User{...}` (linear ownership) | `goxrt.AllocUnique(User{...})` | Slab-allocated free-list pool; immediate deterministic reclamation at point of last use. |
| **ARC** | `&Shared{...}` (multi-owner) | `goxrt.NewBox(Shared{...}, atomic)` | Non-atomic or atomic reference counting; deterministic release when strong count drops to 0. |
| **Stack** | `&Local{...}` (non-escaping) | `&Local{...}` (untouched) | Handled natively by Go compiler escape analysis on the stack frame. |
| **Tracing Fallback** | Unproven / escaping | `&Obj{...}` (untouched) | Conservative fallback to standard Go heap and tracing GC. |

## 4. CLI Toolchain Commands

### 4.1 `gox build`

Compiles a Go package or directory into a standalone native binary with memory-strategy transformations applied:

```bash
# Build current package into executable
gox build .

# Build specific directory with custom output binary name
gox build -o /usr/local/bin/myapp ./cmd/myapp

# Build with verbose transformation logs
gox build -v ./examples/basic

# Retain transformed staging directory in .gox-cache/staging for inspection
gox build -keep-transformed -o server ./examples/basic
```

#### Flags
- `-o <path>`: Output binary path. Defaults to directory name (e.g. `basic` or `app.exe`).
- `-dir <path>`: Project source directory (defaults to current working directory).
- `-keep-transformed`: Retains transformed source files in `.gox-cache/staging` instead of cleaning up temporary directories.
- `-v`: Verbose output detailing discovered allocations, proven GC reductions, and rewritten source files.
- `-closed-world`: Treat CHA dynamic-call targets as complete (default `true` for executables).

### 4.2 `gox run`

Builds and directly executes a Go application with arguments forwarded:

```bash
# Build and run application in current directory
gox run .

# Run application from another directory
gox run -dir ./examples/basic .

# Run application with command-line arguments forwarded
gox run . -- -port 8080 -verbose
```

### 4.3 `gox analyze`

Performs static analysis and produces formal memory strategy reports without modifying source code:

```bash
gox analyze -memory-strategy ./...
gox analyze -memory-strategy -explain ./...
gox analyze -explain-alloc <id> ./...
gox analyze -format json -output gox-report.json ./...
```

## 5. End-to-End Walkthrough Example

Consider the following standard Go program (`examples/basic/main.go`):

```go
package main

import "fmt"

type User struct {
    Name   string
    Friend *User
}

var cached *User

func localGreeting(name string) string {
    user := &User{Name: name}
    return "hello " + user.Name
}

func newUser(name string) *User {
    return &User{Name: name}
}

func cacheUser(name string) {
    cached = &User{Name: name}
}

func main() {
    fmt.Println(localGreeting("Gopher"), newUser("GOX").Name)
    cacheUser("cached")
}
```

Running `gox build -keep-transformed -v .` yields:

1. **Analysis**:
   - `localGreeting`: `user := &User{Name: name}` is proven **Stack** safe (0 escapes). Left untouched for stack allocation.
   - `newUser`: `&User{Name: name}` is proven **Caller-Owned Unique** memory. Rewritten to `goxrt.AllocUnique(User{Name: name})`.
   - `cacheUser`: `&User{Name: name}` is proven **Immortal Static Data**. Rewritten to `goxrt.AllocImmortal(User{Name: name})`.
   - **Proven GC Reduction**: **100.0%**.

2. **Transformed Source**:
```go
package main

import "fmt"
import goxrt "example.com/gox-basic/goxrt"

type User struct {
    Name   string
    Friend *User
}

var cached *User

func localGreeting(name string) string {
    user := &User{Name: name}
    return "hello " + user.Name
}

func newUser(name string) *User {
    return goxrt.AllocUnique(User{Name: name})
}

func cacheUser(name string) {
    cached = goxrt.AllocImmortal(User{Name: name})
}

func main() {
    fmt.Println(localGreeting("Gopher"), newUser("GOX").Name)
    cacheUser("cached")
}
```

3. **Execution**:
   The generated native binary executes with zero garbage collector invocation for all 4 allocation sites!
